## Why

The read half of DEF-011 is the last open piece of the 0.9.1 defect fold. `RopeBuffer.unsafeCharacter(at:)` and its `SendableRopeBuffer` twin delegate to `TextRope.composedCharacterSequence(at:)` (`Sources/TextBuffer/TextRope+ComposedSequences.swift:41-46`), and since `9570025` every call — even reading one plain ASCII letter surrounded by ASCII — pays the full composed-sequence machinery: a scalar-alignment block read, a trail-surrogate probe, materialization of a ±128-UTF-16-unit window through `content(in:)`, an `NSString` bridge, and `rangeOfComposedCharacterSequence`. That is ~5× slower per call than pre-0.9.0 and than `MutableStringBuffer.unsafeCharacter(at:)`, on a path consumers hit per keystroke and per syntax-highlighting scan. The overwhelmingly common case — a printable ASCII code unit with printable ASCII neighbors — needs none of it.

DEF-011's read half was deferred as "benchmark-driven" (DEFECTS.md triage, 2026-07-31), pending the composed-read machinery settling. It has settled: `fix-composed-sequence-reads` fixed the windowing semantics, `foundation-free-textrope` gave TextBuffer the `package`-scoped `utf16CodeUnits(in:)` block-read primitive, and both are archived. **Decision recorded by this change: in-repo benchmarks satisfy the "benchmark-driven" condition.** `MutableStringBuffer` is the per-call reference — it is already the correctness oracle for every drift test — and the repo already pins performance claims with a tolerance-disciplined ratio test (`testBulkInsertCostGrowsLinearlyWithInsertedLength`, `Tests/TextRopeTests/TextRopeInsertTests.swift:397`, landed by `perf-rope-equality-and-bulk-insert` in `3f4b8e4`). No external consumer profile is required to justify removing a ~5× constant from the hot read path.

## What Changes

- **Conservative simple-cluster fast path** in `TextRope.composedCharacterSequence(at:)` (TextBuffer target). One block read of at most three code units — `utf16CodeUnits(in: max(0, k-1) ..< min(utf16Count, k+2))` — and if the previous, current, and next units are **all** printable ASCII (`0x20...0x7E`; a missing neighbor at a document edge counts as safe), return `String(UnicodeScalar(current))` directly: no window, no `NSString`, at most one tree descent. Anything else — controls including CR/LF, surrogates, any non-ASCII unit — falls through to the existing `expandingWindow` path, byte-for-byte unchanged. The fast path changes **no observable result** at any offset of any document; the spec delta's core is a parity requirement.
- **Benchmarks — the deliverable that closes the "benchmark-driven" deferral.** (a) A size-independence ratio test: per-call `unsafeCharacter(at:)` time on a 1 MiB versus a 4 MiB ASCII document must not scale with document size, with the same tolerance discipline as the existing insert ratio test (min-of-N timing, warm-up, noise-floor skip, generous bound). (b) A comparative measurement against `MutableStringBuffer.unsafeCharacter(at:)` on identical ASCII, emoji, and regional-indicator documents, **reported via test-log print** (the `TextRopeStressTests` summary-print precedent), not hard-asserted — cross-implementation wall-clock assertions are flaky by construction. Before/after numbers are recorded in tasks.md's verification step and in the CHANGELOG entry.
- **Red-first honesty — which tests are red-first and which are measurement-only.** None of the automated assertions in this change is red on current `main`, and the tasks say so rather than pretending otherwise. The current implementation's cost is already per-call **constant** (the window is a fixed ±128 units; only the O(log n) descent grows with document size), so the size-independence ratio test passes today — it is added as a permanent regression pin so the fast path can never silently regress to document-scaled work, not as a red test. The honest red signal is the **comparative measurement**: ~5× versus `MutableStringBuffer` on ASCII before, near-parity after. Per the DEF-011 precedent established by `perf-rope-equality-and-bulk-insert` (whose ratio test also turned out green-first and was kept as the pin, with the measured 4.01× ratio recorded in its tasks), the comparative gap is captured as before/after measurements in tasks.md, not as a brittle cross-implementation assertion.
- **Correctness net.** All existing drift sweeps (`Tests/TextBufferTests/RopeBufferDriftTests.swift` — `assertUnsafeCharacterMatches`, the regional-indicator sweeps, the cap-fallback sweep) must stay green. A new **mixed-content boundary sweep** compares `unsafeCharacter(at:)` on both rope buffers against `MutableStringBuffer` at **every** offset of a document that interleaves printable ASCII with emoji (surrogate pairs), combining marks, ZWJ chains, CRLF line breaks, and regional-indicator runs — so every fast-path/slow-path boundary, including offsets where an ASCII unit sits adjacent to non-ASCII and the triple check must conservatively fall through, is pinned against the oracle. This sweep lands and runs green **before** the fast path is implemented, then guards it.
- **Spec deltas.** `rope-utf16-navigation` gains the fast-path contract (parity, at-most-one-block-read, fall-through conditions, size-independent per-call cost); `rope-buffer-drift` gains the mixed-content every-offset sweep requirement, which no existing drift requirement mandates (current read-drift sweeps each cover a single feature per document, and none covers CRLF at all).

### Modified Capabilities
- `rope-utf16-navigation`: adds the simple-cluster fast-path requirement for `composedCharacterSequence(at:)` — result parity with full-document `NSString` expansion at every offset, at most one block read of at most three code units on the fast path, mandatory fall-through to the windowed path for anything outside printable ASCII, and per-call cost independent of document size
- `rope-buffer-drift`: adds a mixed-content every-offset point-read sweep requirement — ASCII interleaved with emoji, combining marks, ZWJ chains, CRLF, and regional-indicator runs, every offset compared against `MutableStringBuffer` on both `RopeBuffer` and `SendableRopeBuffer`, including the ASCII offsets adjacent to non-ASCII where the fast path's conservatism is exercised

## Impact

- **Modified source:** `Sources/TextBuffer/TextRope+ComposedSequences.swift` only — the fast path is a guard block at the top of `composedCharacterSequence(at:)`, after its existing bounds precondition; `expandingWindow` and everything below it are untouched. The fast path itself needs no Foundation (it reads code units through the `package`-scoped `TextRope.utf16CodeUnits(in:)` and builds the result with `String(UnicodeScalar(_:))`), though the file keeps its `import Foundation` for the window path.
- **Modified tests:** `Tests/TextBufferTests/RopeBufferDriftTests.swift` (mixed-content every-offset sweep in the existing `MARK: - Composed Character Sequence Reads` block)
- **New test file:** `Tests/TextBufferTests/RopeReadPerformanceTests.swift` (size-independence ratio pin plus the comparative measurement report)
- **API surface:** unchanged — no signatures move, nothing new is public
- **Behavioral compatibility:** no observable change; the parity requirement in the spec delta is the contract. `composedCharacterSequences(in:)` and `content(in:)` are explicitly untouched (see design Non-Goals: the range form's cost is dominated by extraction and expansion of a caller-chosen span, not by a fixed window constant, so it gets measured before it gets a fast path).
- **Defects closed:** DEF-011 in full — the insert half was closed by `perf-rope-equality-and-bulk-insert`; this closes the read half and removes the last deferred bullet.
- **Explicitly not addressed:** DEF-012's O(log n) `lineRange`/`wordRange` (deferred to M3 Rope Queries); any change to the regional-indicator anchoring, walk cap, or window-length precondition established by `fix-composed-sequence-reads`.
- **Coordination:** none pending — all upstream changes (`fix-composed-sequence-reads`, `foundation-free-textrope`) are archived and released in 0.10.0. CHANGELOG.md and DEFECTS.md edits ride this change alone.
