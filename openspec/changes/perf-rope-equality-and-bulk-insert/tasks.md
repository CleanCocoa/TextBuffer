## 2. Insert: single-pass re-chunk on leaf overflow (DEF-011, insert half)

> Implementation note (2026-08-03): `fix-rope-split-point` landed the single-pass re-chunk ahead of this change — at its HEAD, `insertIntoLeaf` already returns `[Node]` via `chunkLeaves`, `insertIntoNode` already batch-inserts siblings, and the repeated-`splitLeaf` `while` loop is gone. Tasks 2.5/2.6/2.8 were verified satisfied rather than implemented here; 2.1 passed green on first run (1 MiB 16.7 ms, 4 MiB 67.2 ms, ratio 4.01 ≈ linear), confirming it.

- [x] 2.1 Write a red perf test in `Tests/TextRopeTests/TextRopeInsertTests.swift` — *optional, may be dropped if unstable on CI*. Insert 1 MiB and 4 MiB of ASCII at an offset inside a middle leaf of a multi-leaf rope, measure each with `ContinuousClock`, and assert the 4× input costs less than 8× the time (linear ≈4×, the current quadratic ≈16×). Guard against timer noise by skipping the assertion if the 1 MiB baseline measured under a few milliseconds. This is the only task expected to fail before 2.5

Assert `rope.content` equals the expected spliced `String`, then `verifyTreeInvariants(rope)` — which, after `fix-rope-split-point`, checks chunk bounds per ADR-012 (every chunk within `[minChunkUTF8, maxChunkUTF8]` wherever a conforming `Character` boundary exists, with the provable-starvation carve-out), `\r\n` never split across leaves, per-node summary consistency, uniform leaf depth, and child-count bounds (`Tests/TextRopeTests/TreeInvariantValidation.swift`).
